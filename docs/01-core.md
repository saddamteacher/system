# 01 - Core: logging, panic, descriptor tables, traps

After this phase the kernel can describe what it is doing and, when the CPU
raises an exception, report it and stop instead of silently resetting.

## Boot sequence

`kmain` (`kernel/main.c`) is the composition root:

1. `serial_init()`, then `log_set_sink(serial_write)`: logging works.
2. `arch_boot_problem()`: panic if the bootloader handoff is unusable.
3. `arch_cpu_init()`: GDT, TSS and IDT are ours from here on.
4. Run the self-test named by `test=<name>` on the command line, if any.

## Serial driver

`kernel/drivers/serial` owns the 16550 UART logic: divisor latch, line
format, FIFO, polling the "transmit register empty" bit. How the eight
registers are reached is platform-specific, so the driver calls
`arch_debug_uart_read/write(reg)`; on x86_64 these are port I/O at
`0x3F8 + reg`. The driver translates `\n` to `\r\n`.

The driver has no lock. The device is used only by the log, which serialises
access with its own lock.

## Formatting and the log

`kvformat` (`core/printf.c`) is the single formatter. It pushes characters
into a callback, so the same code serves `ksnprintf` (callback writes into a
bounded buffer) and the log (callback fills a 128-byte chunk on the caller's
stack and flushes it to the sink). No heap is needed.

Supported: `%c %s %d %i %u %x %X %p %%`, flags `-` and `0`, a width, and
lengths `l`, `ll`, `z`. No precision, no floating point. The `format`
attribute on every printf-like function makes the compiler check arguments
against the format string, and `-Werror` turns a mismatch into a build error.

`log_write` holds the log spinlock for a whole message, so lines never
interleave.

## Spinlock

`core/spinlock.h` is a test-and-set lock on a C11 `atomic_flag` that also
disables interrupts while held (`arch_irq_save` / `arch_irq_restore`). Without
that, an interrupt handler that logs while the interrupted code holds the log
lock would spin forever. Save/restore rather than disable/enable keeps nested
critical sections correct.

## GDT and TSS

Segmentation does not translate addresses in 64-bit mode, but the GDT is
still required: code segment descriptors select the privilege level and
64-bit mode, and the TSS descriptor locates the TSS.

| Selector | Entry |
|---|---|
| `0x00` | null (required) |
| `0x08` | kernel code |
| `0x10` | kernel data |
| `0x18` | user data |
| `0x20` | user code |
| `0x28` | TSS (occupies two slots) |

User data sits before user code because `sysret` (Phase 5) derives both
selectors from one base and expects that order.

Segment registers cache their descriptor, so after `lgdt` each one must be
reloaded. `CS` cannot be loaded with `mov`; `gdt_load` (`lowlevel.asm`)
rewrites its own return into a far return, which pops both `rip` and `cs`.

The TSS provides two Interrupt Stack Table entries: one for double faults, one
for NMIs. A gate that names an IST slot makes the CPU switch to that stack
unconditionally. A double fault usually means the current stack is unusable;
handling it there would fault again and reset the machine (triple fault).

## IDT and interrupt entry

All 256 vectors point at stubs generated by a NASM `%rep` loop
(`isr.asm`). A stub pushes a dummy error code if the CPU did not push a real
one, pushes its vector number, and jumps to `isr_common`, which saves the 15
general purpose registers and calls `trap_dispatch` with a pointer to the
resulting `struct arch_trap_frame`. On return it restores everything and
executes `iretq`.

Gates are interrupt gates, so interrupts are disabled on entry.

Stack alignment: the CPU aligns `rsp` to 16 bytes before pushing its 5 words;
with error code, vector and 15 registers that is 22 words, so `rsp` is aligned
again at the `call`, as the ABI requires.

## Traps and panic

`trap_dispatch` (arch) translates the frame into an `arch_trap_info` (name,
vector, error code, fault address from `CR2` for page faults) and calls the
kernel upcall `kernel_handle_trap` (`core/panic.c`):

- Breakpoint (`#BP`): logged, then execution resumes. This exercises the full
  save/restore/`iretq` path.
- Anything else, including vectors 32-255 while no interrupt source is
  enabled: panic.

A panic prints the reason, the registers (obtained through
`arch_trap_registers`, so the portable code knows no register names) and a
stack trace, then signals failure to the check runner and halts.

The stack trace follows the frame-pointer chain: with `-fno-omit-frame-pointer`
every function starts with `push rbp; mov rbp, rsp`, so `[rbp]` is the
caller's frame pointer and `[rbp+8]` the return address. `_start` zeroes
`rbp`, which ends the chain. `arch_stack_walk` refuses frame pointers outside
the kernel half or misaligned, so a corrupted chain ends the trace instead of
faulting.

Two hazards are handled explicitly:

- **Log lock held by the crashed code.** `panic` switches the log into panic
  mode, which bypasses the lock.
- **Panic inside panic.** A flag detects re-entry, prints one line and halts.

## Self-tests

`kernel/tests` holds tests run inside the kernel, one per boot.

| Test | Expectation |
|---|---|
| `printf` | formatter output matches expected strings, truncation included |
| `cmdline` | key lookup, spacing, prefixes, truncation |
| `breakpoint` | handler logs the trap and returns to the test |
| `divide-by-zero` | clean panic naming `#DE` (vector without error code) |
| `page-fault` | clean panic naming `#PF` with the fault address (vector with error code) |

### A lesson from the divide test

The first version was `volatile int zero = 0; x = 1 / zero;` and did not trap.
Disassembly showed no `idiv`: with a constant dividend of 1 clang computes
`1 / x` by comparison (the result is `x` for 1 and -1, otherwise 0), which is
legal because division by zero is undefined behaviour. Making the dividend
volatile as well forces a real division.

## Not covered by a check

- The double fault and NMI IST stacks are installed but no test triggers
  them; doing so safely needs control over page mappings (Phase 2).
- `TOOLCHAIN=gcc` is still untested.
